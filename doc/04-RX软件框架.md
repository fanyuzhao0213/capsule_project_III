# RX 软件框架

## 1. 设计原则

RX负责绑定SN过滤、12路天线选择、JPEG重组、设备信息生成和STM32转发。RX没有低功耗约束，16 MHz高频时钟、Radio和TIMER1启动后持续运行。

本工程按职责拆成模块。每个模块只有一个私有状态结构体，其他模块只能通过头文件接口访问，主循环不直接读写模块变量。

| 模块 | 唯一状态结构体 | 职责 |
| --- | --- | --- |
| `receiver_timebase` | `receiver_timebase_state_t` | TIMER1统一时间基 |
| `radio_link` | `receiver_radio_state_t` | Radio硬件、收发切换和包队列 |
| `antenna_manager` | `receiver_antenna_state_t` | 发现、协商扫描、候选和失联恢复 |
| `image` | `receiver_image_state_t` | 图片重组、校验、ACK和设备信息 |
| `uart_bridge` | `receiver_uart_state_t` | STM控制接收、控制路由和图片DMA发送 |
| `binding_storage` | `receiver_binding_state_t` | 当前会话绑定SN |
| `rf1662` | `rf1662_state_t` | 12路开关驱动及当前通道 |

## 2. 初始化顺序

`receiver_application_init()`按依赖关系执行：

1. 启动16 MHz高频晶振。
2. 初始化RTT日志。
3. 清空RAM绑定状态。
4. 初始化图片模块状态。
5. 初始化RF1662，默认选择ANT1。
6. 初始化收发模式控制脚。
7. 初始化TIMER1统一时间基。
8. 配置UARTE RXDRDY到TIMER1 CC1的PPI捕获。
9. 初始化1 Mbps UART。
10. 初始化2400 MHz、2 Mbit/s Radio并开始接收。
11. 初始化天线管理器，进入未绑定发现状态。

## 3. while主循环

主循环本身只做调度和空闲等待：

```c
while (true)
{
    bool worked = receiver_application_run_once();
    bool log_worked = NRF_LOG_PROCESS();

    if (!worked && !log_worked)
    {
        __WFE();
    }
}
```

`receiver_application_run_once()`的固定顺序如下：

```text
1. antenna_service_events   处理Radio中断捕获的END或0x11
2. radio_process_one        从队列解析一个无线业务包
3. uart_rx_service          收集并解析STM32控制包
4. uart_control_service     图片发送空闲后补发短控制应答
5. uart_tx_service          最多启动一个图片DMA块
6. antenna_service_events   立即处理本轮无线包产生的新事件
7. antenna_service_schedule 按4 ms节拍推进天线状态机
```

每项服务单次工作量有限。Radio中断捕获的扫描事件在业务处理前后各检查一次，使RX能尽快利用TX在END后的30 ms接收窗口发送`0x12`。

## 4. 中断职责

### 4.1 TIMER1

RX只使用一个通用硬件定时器TIMER1：

| 资源 | 用途 |
| --- | --- |
| 计数频率 | 1 MHz，1计数为1 us |
| CC0 | 每1 ms触发中断 |
| CC1 | PPI捕获最后一个UART字节到达时刻 |
| CC2 | 中断中捕获当前自由运行计数 |

`TIMER1_IRQHandler()`只更新时间、累计4 ms天线调度节拍、检查100 ms UART静默并安排下一次1 ms比较。它不切换天线、不解析协议、不打印日志。

### 4.2 Radio

`RADIO_IRQHandler()`完成以下工作：

1. 读取CRC结果和RSSI。
2. 把包交给天线管理器检查。
3. `SEEK_END`状态只捕获匹配END或`0x11`，不统计RSSI。
4. `FAST_SCAN`状态只统计CRC正确、SN匹配的`0x05`。
5. 其他状态把合法包放入Radio环形队列。
6. 立即恢复下一包接收。

图片解析、ACK和UART封装都在主循环完成。

### 4.3 UART

UART事件只把字节搬入软件环形缓冲、记录错误和置位DMA发送完成标志。完整控制帧解析在主循环执行。

PC 的 `ZAYS 2C` 天线测试命令经 STM32 转发后由 RX 本地处理。测试期间手动选择 ANT1～ANT12，不让自动扫描状态机抢占选路；`0D` 停止后恢复自动流程。完整帧、ID 和固定 `0x49` 回包见 [PC到RX天线测试协议](09-PC到RX天线测试协议.md)。

## 5. 天线状态机

```text
未绑定
  DISCOVERY
      │ 绑定SN
      ▼
  SEEK_END ──捕获匹配END并发送0x12──► 等待TX的0x11
      ▲                                      │
      │                                      ▼
      └────候选耗尽或扫描无样本──── FAST_SCAN
                                             │
                                  12路×32 ms×4轮
                                             ▼
                                          LOCKED
                                             │
                              当前候选失效则尝试下一候选
```

### 5.1 DISCOVERY

未绑定时每路驻留650 ms寻找任意SN广播。发现SN后在当前通道保持1500 ms，便于STM和上位机稳定看到该设备。绑定完成后进入`SEEK_END`。

### 5.2 SEEK_END

每路驻留8 ms，12路循环5轮为一批，单批名义轮询时间为`8×12×5=480 ms`。这里只寻找绑定胶囊的图片END或快速扫描通知：

- 不把普通图片包送入图片重组模块；
- 不统计任何RSSI；
- 一批没有找到END时直接开始下一批，不退出；
- 捕获END后在该通道发送两次`0x12`，并按`RF1662_SCAN_REQUEST_HOLD_MS=150 ms`保持当前天线等待TX回复；
- 最多使用两个END窗口请求。

这里的5轮只是轮询批次边界，不是正式天线测量次数。

### 5.3 FAST_SCAN

TX接受`0x12`后发送`0x11`并进入1.8秒快速SN广播。RX收到SN匹配的`0x11`后开始正式扫描：

- 每路32 ms；该值与4 ms天线服务节拍整除，截止检查不会额外向后取整；
- 12路循环4轮；
- 总驻留时间为`12×32 ms×4=1536 ms`；
- 只统计CRC正确、SN匹配的`0x05`广播；
- 每路保存有效样本数和RSSI幅值总和；
- 扫描完成后计算平均值并保存最新12路RSSI；
- 按样本可靠性、平均RSSI和样本数选出前三候选。

RSSI寄存器保存负dBm的幅值，数值越小信号越强。例如26表示-26 dBm，比36表示的-36 dBm更强。

### 5.4 LOCKED

RX锁定最佳候选接收图片。满足任一条件时切换到下一候选：

- 1500 ms没有收到绑定设备的有效包；
- 4000 ms没有完成一幅图片；
- 失败帧累计达到3帧。

前三候选全部失效后回到`SEEK_END`，重新与TX协商扫描。正常接收期间不做固定周期重扫。

## 6. 图片状态机

`image`模块内部包含一个当前图片帧状态：

- `BEGIN`：校验长度和分片数，保存帧ID、SN、TX版本、加速度及开始时间，清空分片位图。
- `DATA`：校验帧ID和SN，按分片位图去重后复制JPEG数据。
- `END`：确认所有分片到齐，校验JPEG累加和，发送`0x10` ACK或待协商时发送`0x12`。
- 校验成功：生成128字节设备信息，并把设备信息和JPEG交给UART模块。

图片模块不操作UART DMA缓冲，也不维护Radio接收队列。

## 7. UART桥接

### 7.1 STM到RX

- UART为1 Mbps、8N1。
- PPI在每个物理字节到达时把TIMER1计数捕获到CC1。
- 最后一个字节后连续100 ms无数据，判定当前包结束。
- 主循环校验ZAYS帧头、长度和校验和。
- `0x20～0x25`在RX本地处理；`0x40～0x46`通过Radio转发到TX。

### 7.2 RX到STM

完整图片封装为`0x81`帧后保存在UART模块内部发送缓冲。主循环每轮最多启动一个255字节EasyDMA块，`APP_UART_TX_EMPTY`确认上一块发送完毕后再启动下一块。

短控制应答遇到图片正在发送时进入一个独立待发送槽，图片结束后补发。

## 8. 设备信息中的天线数据

| 偏移 | 内容 |
| --- | --- |
| 39～44 | ANT1～ANT6 RSSI |
| 49 | 当前天线号，范围1～12；数值2就是ANT2 |
| 50 | 频率偏移，当前0表示2400 MHz |
| 51～56 | ANT7～ANT12 RSSI |

正式扫描完成前保留上一轮完整扫描结果；新绑定会清空旧结果。锁定后收到匹配包时，仅实时更新当前通道RSSI，其他通道保持最近完整扫描值。

## 9. 关键参数

参数以当前 `receiver/config.h`、`legacy_protocol.h`、`antenna_manager.c` 和 `rf1662.c` 为准。

| 宏或常量 | 当前值 | 单位 | 设置位置 | 实际作用与修改注意事项 |
| --- | ---: | --- | --- | --- |
| `RADIO_FREQUENCY_MHZ` | 2400 | MHz | `config.h` | Radio中心频率；TX必须同步修改 |
| Radio速率 | 2 | Mbit/s | `radio_link.c`初始化 | 必须与TX一致 |
| `RADIO_PACKET_SIZE` | 254 | 字节 | `config.h`→协议常量 | Radio固定载荷长度；TX必须一致 |
| `RADIO_QUEUE_DEPTH` | 8 | 包 | `config.h` | 主循环尚未处理时可暂存的Radio包数量 |
| `RECEIVER_ACK_TX_POWER` | -8 | dBm | `config.h` | RX发送`0x10`或`0x12`时的功率 |
| `RF1662_DEFAULT_ANTENNA` | 0 | 索引 | `config.h` | 上电选择ANT1；软件索引0～11对应ANT1～ANT12 |
| `RF1662_DISCOVERY_DWELL_MS` | 650 | ms/路 | `config.h` | 未绑定发现驻留；覆盖TX的500 ms常态SN周期，并保留150 ms余量 |
| `RF1662_DISCOVERY_FOUND_HOLD_MS` | 1500 | ms | `config.h` | 发现任意SN后继续停在当前天线，便于STM/上位机接收重复广播 |
| `RF1662_SEEK_END_DWELL_MS` | 8 | ms/路 | `config.h` | 绑定后逐路寻找目标END或`0x11` |
| `RF1662_SEEK_END_ROUNDS` | 5 | 轮/批 | `config.h` | 单批名义时间`8×12×5=480 ms`；一批结束仍未找到则继续下一批 |
| `RF1662_SCAN_REQUEST_HOLD_MS` | 150 | ms | `config.h` | 捕获END并发送`0x12`后保持当前天线，等待TX接收请求并返回`0x11` |
| `RF1662_FAST_SCAN_DWELL_MS` | 32 | ms/路 | `config.h` | 正式RSSI扫描单路窗口；与4 ms服务节拍整除 |
| `RF1662_FAST_SCAN_ROUNDS` | 4 | 轮 | `config.h` | 正式扫描总驻留时间`12×32×4=1536 ms` |
| `RF1662_MIN_RSSI_SAMPLES` | 2 | 包/路 | `config.h` | 至少2个CRC正确且SN匹配的`0x05`才作为可靠候选 |
| `RF1662_SERVICE_TICK_MS` | 4 | ms | `config.h` | 天线状态机调度粒度；驻留时间最好取4 ms整数倍 |
| `RF1662_TARGET_PACKET_TIMEOUT_MS` | 1500 | ms | `config.h` | LOCKED状态未收到目标有效包时切换候选 |
| `RF1662_COMPLETE_IMAGE_TIMEOUT_MS` | 4000 | ms | `config.h` | LOCKED状态长期无完整图片时切换候选 |
| `RF1662_FAILED_FRAME_LIMIT` | 3 | 帧 | `config.h` | 连续失败帧达到阈值时切换候选 |
| `RF1662_SCAN_DWELL_MS` | 650 | ms | `config.h` | 旧启动扫描遗留参数；当前天线状态机未引用，修改不会改变现有流程 |
| `UART_RX_IDLE_TIMEOUT_US` | 100000 | us | `config.h` | STM最后一个字节后静默100 ms，才把累计数据判定为一个接收块 |
| `UART_TX_DMA_CHUNK_SIZE` | 255 | 字节 | `config.h` | 单次EasyDMA发送上限；1 Mbps、8N1时线速发送约2.55 ms/块 |
| `UART_RX_BUFFER_SIZE` | 256 | 字节 | `config.h` | UART ISR环形缓冲区，必须为2的幂 |
| `UART_RX_PACKET_MAX_SIZE` | 1024 | 字节 | `config.h` | 一次静默分包允许累计的最大字节数 |
| TIMER1比较周期 | 1000 | us | `receiver_timebase.c` | 形成1 ms软件时间，并累计4 ms天线服务节拍 |
| `RF1662_BIT_DELAY_US` | 2 | us | `rf1662.c` | RF1662两线串行位时序，沿用旧工程验证值 |
| `RF1662_START_DELAY_US` | 12 | us | `rf1662.c` | RF1662起始序列每阶段延时，为`2 us×6` |
| RF1662初始化延时 | 20、10、1000 | us | `rf1662.c` | GPIO稳定、STARTUP到ACTIVE、立即切换模式稳定时间；均为旧工程时序 |

### 9.1 时间窗口配合关系

| 场景 | RX参数 | TX对应参数 | 配合关系 |
| --- | --- | --- | --- |
| 未绑定发现 | 650 ms/路 | 常态SN/图片周期500 ms | 单路窗口覆盖至少一次TX广播机会 |
| END协商 | SEEK_END 8 ms/路；请求后保频150 ms | END后ACK窗口30 ms | `0x12`必须在TX的30 ms窗口内发出；150 ms用于RX保持该天线等待后续`0x11`，不是延迟发送请求 |
| 正式扫描 | 32 ms/路×12路×4轮=1536 ms | 快速广播窗口1800 ms | TX窗口比正式扫描多264 ms，覆盖协商启动和主循环调度余量 |
| RSSI样本 | 32 ms/路 | TX每8 ms广播一次`0x05` | 每路理论覆盖4个广播周期；可靠候选至少需要2个有效样本 |
| 锁定监测 | 包超时1500 ms；完整图超时4000 ms；失败3帧 | TX图片周期500 ms | 分别约对应3个发图周期、8个发图周期及连续失败阈值 |
| UART收包 | 静默100 ms | STM发送节奏 | 包内相邻字节间隔必须明显小于100 ms，否则会被拆成两个数据块 |

时间参数的单位并不统一：天线和链路业务主要使用ms，UART静默和RF1662底层时序使用us。修改时不要只改数值而忽略单位。`RF1662_FAST_SCAN_DWELL_MS`已经设置为4 ms服务节拍的整数倍；新增驻留参数也建议保持这一约束。

## 10. 阅读代码顺序

1. `main.c`：只看初始化和主循环任务顺序。
2. `antenna_manager.c`：理解四个天线状态及转换条件。
3. `radio_link.c`：理解中断如何分流到天线管理或业务队列。
4. `image.c`：理解BEGIN、DATA、END和设备信息生成。
5. `uart_bridge.c`：理解STM控制链路和图片DMA发送。
6. `receiver_timebase.c`：理解统一1 ms时间基和UART静默检测。
7. `binding_storage.c`、`rf1662.c`：最后看两个简单底层模块。

协议字段和命令定义统一查看`legacy_protocol.h`及`01-通信协议.md`。
