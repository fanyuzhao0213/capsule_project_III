# PC → RX 手动天线测试协议

## 1. 链路与用途

```text
PC 上位机 ──USART3──> STM32 ──USART2──> nRF RX ──RF1662──> ANT1～ANT12
PC 上位机 <──USART3── STM32 <──USART2── nRF RX
```

STM32 对命令 `0x2C` 不做天线控制，仅把完整帧转发 RX；RX 本地解析并切换天线，不向胶囊 TX 发送这条命令。RX 的应答经 STM32 的控制帧 pending 缓冲转发给 PC。此协议用于产测/调试，与 RX 正常的自动天线发现、快速扫描和候选选路分开。

## 2. PC 请求帧

| 偏移 | 字节数 | 内容 | 说明 |
| --- | ---: | --- | --- |
| 0～3 | 4 | `5A 41 59 53` | ASCII `ZAYS` |
| 4 | 1 | `2C` | 手动天线测试命令 |
| 5～6 | 2 | `00 01` | Payload 长度为 1，大端 |
| 7 | 1 | ID | 见下表 |
| 8 | 1 | Checksum | 仅对 Payload 累加取低 8 位；本命令等于 ID |

| ID | 操作 |
| --- | --- |
| `00` | 设置“已开始测试”标志，进入手动模式，保持当前天线不变 |
| `01`～`0C` | 仅在收到 `00` 后选择 ANT1～ANT12；否则拒绝，不切换天线 |
| `0D` | 清除“已开始测试”标志，退出手动模式，按当前绑定状态重新启动自动选路 |

示例：

```text
开始： 5A 41 59 53 2C 00 01 00 00
ANT1：5A 41 59 53 2C 00 01 01 01
ANT12：5A 41 59 53 2C 00 01 0C 0C
停止： 5A 41 59 53 2C 00 01 0D 0D
```

## 3. RX 固定应答

对校验正确、长度为 1 且当前状态允许执行的 `00`～`0D` 命令，RX 完成状态切换或选路后回复：

```text
5A 41 59 53 49 00 00 00
```

该帧为 `ZAYS + 0x49 + 0 字节 Payload + 0x00 Checksum`，总长 8 字节。RX 在图片 UART 发送繁忙时按应答次数排队，待短帧通道空闲后逐条发给 STM32。STM32 在 PC 图片 DMA 空闲后转发。

STM32 当前只有一帧控制应答 pending 缓冲。PC 应逐条发送测试命令，收到对应回包后再发下一条，不要一次性连续发送多条并期待逐条回包。

`0x49` 与当前框架的通用控制错误应答命令号相同，**仅凭回包无法区分天线测试成功和其他控制错误**。上位机应结合当前请求及超时判断；如果后续需要失败原因或当前天线号，必须另行扩展应答协议。错误长度、错误校验、非法 ID 或尚未收到 `00` 时的选路命令都不触发切换，也不发测试应答。

## 4. RX 状态处理

- 手动模式中暂停自动 `DISCOVERY / SEEK_END / FAST_SCAN / LOCKED` 调度和失联换路，但无线接收及正常图片解析仍在选定的天线上运行。
- 收到 `00` 或切换测试天线时清空12路旧RSSI；此后有效无线包只刷新当前天线的最新值。手动测试期间，图片 DeviceInfo 中当前天线对应的RSSI为最新值，其余11路固定为0；固定 `0x49` 回包本身不包含 RSSI。
- 每次换路清空旧无线接收队列和未完成图片，防止将切换前后的分片拼成同一张图；已经排队的 UART 图片不强行中断。
- 测试期间若发生 SN 绑定变化，保持手动选路；收到 `0D` 后再依据新的绑定状态恢复发现或寻 END。
- `00` 和 `0D` 可重复发送；`01`～`0C` 必须在 `00` 之后发送。PC 按“开始 → 逐路选择 → 停止”顺序使用，并在退出测试界面时发送停止命令。

实现位置：`stm32F103RET6/stm_project/Core/Src/capsule_protocol.c`（PC 命令转发、RX 应答转发），`nrf_rx/examples/peripheral/radio/receiver/uart_bridge.c`（命令校验与应答），`antenna_manager.c`（手动测试状态和 RF1662 选路）。
