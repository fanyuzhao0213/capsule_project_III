# 当前工程与TYGD31旧工程对比

## 1. 核心参数

| 项目 | 当前工程 | TYGD31旧工程 |
| --- | --- | --- |
| 无线频段 | 2.4 GHz，当前2400 MHz | 2.4 GHz，支持运行时频率值 |
| 当前图片周期 | 500 ms | 由旧时间调度控制，未采用当前统一宏 |
| TX低功耗 | RTC唤醒、CPU WFE、摄像头休眠、SPI按需启停、短RX窗口 | 有传感器休眠，整体外设和CPU低功耗管理较弱 |
| CX93510空闲控制 | P0.11帧RAM保持高；图片事务结束后关闭nRF SPIM0 | 每帧把整张JPEG搬入nRF RAM后拉低旧板P0.18 PDRAM；SPI0保持初始化和开启 |
| 图片发送时的数据源 | 每个DATA分片直接读取CX93510帧RAM | 从nRF全局`image_buff[]`读取整图副本 |
| 天线数量 | 12路 | 12路，数组容量16路 |
| TX参与扫描 | 收到合法请求后暂停图片并快速广播SN | 不参与，继续正常发送 |
| 扫描样本 | 绑定SN且CRC正确的SN包 | `radio_rssi_value>0`，扫描函数本身不按绑定SN筛选 |
| RSSI统计 | 多样本平均值 | 扫描期单路最强值 |
| 候选数量 | 前三路 | 一路 |
| 失联恢复 | 先切候选，再请求正式扫描 | 1200 ms无完整图片后直接重新扫描 |
| 设备信息 | 保存12路最近正式扫描结果，当前路持续更新 | 保存扫描数组，锁定路按检测周期更新 |

## 2. 扫描时序

| 阶段 | 当前工程 | TYGD31旧工程 |
| --- | --- | --- |
| 初始寻找 | 12×8 ms×5轮为一批，零命中重复 | 每3 ms轮换一路 |
| 扫描结束条件 | 协商后固定12×32 ms×4轮 | 全局累计36个正RSSI样本 |
| 名义正式扫描时间 | 1536 ms | 不固定，取决于得到36个有效样本的时间 |
| 每路覆盖 | 固定4个32 ms窗口，但样本数仍取决于收到的SN包 | 不保证均匀覆盖 |
| 选路依据 | 可靠样本优先，然后平均RSSI最强 | 各路记录的单次最强RSSI |

## 3. 当前方案的改进

1. TX只在RX明确请求时增加广播，兼顾低功耗。
2. 正式扫描使用密集SN，避免400～500 ms图片周期与短天线驻留难以对齐。
3. 所有统计必须匹配绑定SN并通过CRC。
4. 平均值比单次极值更稳定。
5. 保存前三候选，胶囊移动时可先快速换路。
6. 12路扫描结果进入128字节设备信息，便于PC观察。

## 4. 当前方案仍存在的边界

- TX只在END后约30 ms接收命令；完全收不到END时，RX无法主动唤醒TX快速广播。
- 12路RSSI不是同一时刻的实时值，而是最近一次扫描的分时采样结果。
- 32 ms驻留、4轮、2个可靠样本阈值仍需通过人体环境和移动测试校准。
- 快速扫描会暂停图片最多1800 ms，PC端应把这段时间识别为选路过程。

## 5. 推荐测试

| 测试 | 通过标准 |
| --- | --- |
| 静止场景 | 连续多次扫描的前三候选基本稳定 |
| 缓慢移动 | 当前路下降后能切到候选并恢复完整图片 |
| 快速移动 | 候选耗尽后能捕获END并重新协商 |
| 弱信号 | 无效CRC和非绑定SN不进入RSSI统计 |
| 功耗 | 正常500 ms模式功耗不因扫描功能常态增加 |
| 扫描窗口 | 快速广播只维持1800 ms，随后自动恢复500 ms图片周期 |

## 6. 结论

当前方案更适合移动胶囊和低功耗TX：正常运行保持500 ms周期与短接收窗口，只有链路需要重新选路时才临时牺牲约1.8秒图片传输完成12路测量。旧方案结构简单，但样本分配、目标过滤和移动恢复能力不足。
