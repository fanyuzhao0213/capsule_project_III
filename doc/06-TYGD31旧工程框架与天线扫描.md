# TYGD31 旧工程 TX/RX 框架与天线扫描

本文是对保留的 `TYGD31-2.4GHZ` 参考工程进行的设计梳理，便于不逐文件阅读源码也能理解旧框架。

## 1. 旧TX框架

旧TX入口非常薄：`main()`初始化中断向量和系统时钟，然后进入 `domain()`。

`domain()`负责驱动：

- 胶囊SN广播；
- 胶囊ID广播；
- 图片采集、发送和重发；
- Radio与串行控制；
- 看门狗和软件时间调度。

图片流程仍是摄像头/CX93510采集、分片发送和ACK重发。旧TX在采集完成或异常时调用传感器休眠，但没有现工程中完整的RTC低功耗任务编排、SPIM0/SPIM1按需关闭和 `WFE` 空闲策略。

### 旧TX摄像头与CX93510时序

旧框架上电时只调用一次 `spi_master_init(SPI0)`。随后 `cx93510_init()`先把旧板PDRAM控制脚P0.18拉低10 ms，再拉高并等待5 ms，最多读取10次 `SLAVE_SEL_CTRL`确认CX93510可访问。若启动失败，代码连续复位并重新初始化SPI0两次后重试；累计10次失败则复位MCU。

CX93510可访问后，旧代码通过它的代理I2C初始化OV7676：XSHUTDOWN在P0.06上先低5 ms、再高5 ms，顺序写完整寄存器表，每项间隔200 us，部分表项另带1 ms延时，最后等待60 ms。旧代码没有读取OV7676芯片ID，也没有执行当前框架的关键寄存器回读校验。初始化结束后再等待10 ms，将PDRAM拉低并再等待10 ms。

每次拍照时，旧代码执行：

```text
PDRAM拉高并等待5 ms
  → 确认SLAVE_SEL_CTRL
  → 重设CX93510压缩率、480×480窗口和单帧参数
  → 开补光灯
  → OV7676写0x0100=1唤醒
  → 固定等待25 ms
  → 启动采集并最多轮询约180 ms
  → OV7676写0x0100=0休眠
  → 关灯
  → 把整张JPEG读入nRF image_buff[]
  → PDRAM拉低
  → 从nRF RAM发送Radio图片
```

旧框架的低功耗重点是逐帧拉低CX93510的PDRAM控制脚，而不是关闭nRF SPI0。正常空闲和每帧结束路径没有SPI disable；SPI复位/重初始化只出现在CX93510启动失败的恢复分支。旧框架可以较早拉低PDRAM，是因为整张JPEG已先复制进nRF RAM。当前框架改为从CX93510帧RAM逐分片发送，所以必须保持P0.11为高，并把节电动作改为图片事务结束后关闭nRF侧SPIM0。

### 旧TX与天线扫描的关系

旧TX没有12路RF1662天线开关，也不执行天线排序。它只是按既有节奏发送图片或SN。天线扫描全部由旧RX自行切换完成，TX与RX之间没有“暂停图片、快速SN广播”的协商命令。

## 2. 旧RX框架

旧RX初始化顺序：

1. 中断向量和系统时钟；
2. nRF驱动；
3. RF1662天线模块；
4. 进入 `domain()` 主循环。

`domain()`处理Radio图片/SN包和UART绑定、解绑、SN设置、频率设置等命令。Radio中断读取 `RSSISAMPLE`，并把CRC正确包送入队列。

## 3. 旧RX天线状态机

旧工程只有两个状态：

- `ANTENNA_STATUS_SCAN`：搜索最强天线；
- `ANTENNA_STATUS_DETECT`：固定当前天线并检查是否持续收到完整图片。

### 扫描参数

| 参数 | 数值 | 含义 |
| --- | ---: | --- |
| 使用天线 | 12 | 数组为16路，实际只循环12路 |
| `ANTENNA_SCAN_TIMES` | 36 | 全局累计的正RSSI样本数 |
| `ANTENNA_RSSI_SCAN_PERIOD` | 3 ms | 扫描回调周期 |
| `ANTENNA_RSSI_UPDATE_PERIOD` | 50 ms | 锁定后的检测回调周期 |
| `ANTENNA_RSSI_DETECT_PERIOD` | 1200 ms | 完整图片健康检查周期 |

### 扫描算法

1. 每次回调读取全局 `radio_rssi_value`。
2. 若值大于0，就把当前天线出现过的最小幅值保存为该路最强RSSI，并让全局样本计数加1。
3. 未满36个有效样本时，切到下一天线。
4. 达到36个有效样本后，在12路中选择非0且幅值最小的一路。
5. 将扫描数组复制到设备信息数组，进入检测状态。

36是所有天线合计的有效样本数，并不保证每路正好3个样本，也不保证所有天线都有值。

### 锁定检测

- 旧RX每收到一张完整图片就增加 `antenna_detect_cnt`。
- 每1200 ms检查一次：若完整图片计数为0，则重新进入扫描；否则更新当前天线在检测周期内的最强RSSI并清零计数。
- 没有前三候选和分级切换，失效后直接重新全扫描。

## 4. 旧设备信息

旧RX将当前天线号写入偏移49，频率寄存器写入偏移50，将RSSI写入39～44和51～60。虽然数组容量和设备信息位置支持16路，实际硬件只使用前12路。

## 5. 旧算法主要风险

- 单次最强值容易受瞬时尖峰影响。
- 36个全局样本无法保证各天线采样均匀。
- 扫描过程没有绑定SN级别的专用统计，RSSI可能不完全代表目标胶囊。
- TX继续发送图片，扫描窗口可能落在图片空闲区。
- 只保留一个候选，移动时恢复需要重新全扫描。
