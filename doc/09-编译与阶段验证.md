## 2. 配套刷写要求

新增的 `0x11`、`0x12` 天线扫描协商需要TX和RX同时升级。只升级一侧时不会形成完整扫描流程。DeviceInfo校验范围的变更还要求RX与STM协议保持一致。

## 3. 编译前检查

1. TX和RX的 `RADIO_FREQUENCY_MHZ` 都是2400。
2. TX的 `IMAGE_PERIOD_MS` 和 `SN_BROADCAST_PERIOD_MS` 都是500。
3. TX/RX的 `legacy_protocol.h` 对命令号和字段偏移定义一致。
4. STM的USART2波特率与RX UART配置一致。
5. Keil目标芯片和下载器配置与实际板卡一致。

## 4. 上机验证顺序

### 基础通信

1. 分别烧录TX、RX、STM。
2. 绑定SN并配置RTC。
3. 验证PC持续收到图片，帧间隔约500 ms。
4. 验证设备信息标识、版本、SN、芯片ID、RTC和加速度字段。

### 天线扫描

1. 绑定后确认RX捕获目标END并发送 `0x12`。
2. 确认TX暂停图片并发出 `0x11` 与密集 `0x05`。
3. 确认RX在约1.44秒内完成12路4轮扫描。
4. 确认设备信息的12路RSSI更新，当前天线编号是1～12。
5. 移动胶囊，验证候选切换和候选耗尽后的重新协商。
6. 确认扫描结束后TX恢复500 ms图片周期。

### 低功耗

分别测量以下状态的TX电流：

- 正常500 ms图片工作；
- 拍照和Radio发送瞬间；
- END后的30 ms ACK窗口；
- 按需1800 ms快速SN扫描窗口；
- 普通空闲睡眠。

快速扫描窗口功耗可以升高，但正常运行平均功耗不应因为扫描功能而持续增加。
