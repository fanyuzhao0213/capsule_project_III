# TYGD31 无线图像链路移植设计说明

## 1 文档目的

本文说明如何将 `TYGD31-2.4GHZ` 原始工程中的 RX、TX 与 STM32 中转存储逻辑移植到现有 `nrf_rx`、`nrf_tx` 和 `stm32F103RET6` 工程。实现以兼容原始无线协议为首要目标，同时保留现有工程的 RTT 日志、UART DMA、环形缓冲和 FatFs 模块。

## 2 工程角色

| 工程 | 处理器 | 角色 | 主要职责 |
| --- | --- | --- | --- |
| `nrf_tx` | nRF52832 | 胶囊发送端 | 驱动 OV7676 和 CX93510、采集 JPEG、分包发送、等待应答和超时重发 |
| `nrf_rx` | nRF52832 | 专用接收端 | 接收 Radio 包、重组 JPEG、校验完整性、发送应答、封装 STM 帧 |
| `stm32F103RET6` | STM32F103RET6 | 中转和存储端 | DMA 接收 nRF 数据、流式解析、JPEG 落盘、向电脑转发、反向转发电脑命令 |

## 3 无线物理层

RX 和 TX 必须使用完全相同的配置。

| 参数 | 配置值 |
| --- | --- |
| 速率 | Nordic 2 Mbit |
| 固定包长 | 254 字节 |
| 数据白化 | 关闭 |
| 字节序 | Big Endian |
| BASE0 | `0xE7E7E7E7` |
| BASE1 | `0x00C2C2C2` |
| PREFIX0 | `0xC4C3C2E7` |
| PREFIX1 | `0xC5C6C7C8` |
| TXADDRESS | 0 |
| RXADDRESSES | bit 0 |
| CRC | 16 位，初值 `0xFFFF`，多项式 `0x11021` |
| 默认频点 | 2400 MHz，`FREQUENCY=0` |
| 序列号配置频点 | 2490 MHz，`FREQUENCY=90` |
| TX 功率 | +4 dBm |
| RX 应答功率 | -8 dBm |

接收板 P0.23 用于外部收发通道控制：低电平为接收，高电平为发送。切换方向时必须先关闭 Radio，调整引脚，再重新执行 TXEN 或 RXEN。

## 4 原始 Radio 图像协议

### 4.1 命令

| 命令 | 值 | 方向 | 说明 |
| --- | --- | --- | --- |
| IMAGE BEGIN | `0x01` | TX 到 RX | 宣告图片编号、长度和包数 |
| IMAGE DATA | `0x80` | TX 到 RX | 携带最多 242 字节 JPEG |
| IMAGE END | `0x03` | TX 到 RX | 携带整图 8 位累加和 |
| IMAGE ACK | `0x10` | RX 到 TX | 确认图片完整接收 |
| IMAGE FORWARD | `0x81` | RX 到 STM/PC | 转发设备信息和完整 JPEG |

### 4.2 开始包

| 偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | `0x01` |
| 1 | 1 | 图片 ID |
| 2 | 8 | 胶囊序列号 |
| 10 | 2 | JPEG 长度，大端 |
| 12 | 2 | 数据包数量，大端 |
| 14 | 240 | 保留并清零 |

开始包发送两次。RX 对同一图片 ID 的重复开始包执行幂等重置，不把它计作数据包。

### 4.3 数据包

| 偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | `0x80` |
| 1 | 1 | 图片 ID |
| 2 | 8 | 胶囊序列号 |
| 10 | 2 | 包编号，大端，从 0 开始 |
| 12 | 242 | JPEG 数据，最后一包不足部分清零 |

RX 使用接收位图去重。写入偏移为 `包编号 × 242`，最后一包只复制剩余的有效长度。

### 4.4 结束包与应答

结束包的字节 0 为 `0x03`，字节 1 为图片 ID，字节 2 至 9 为序列号，字节 10 为 JPEG 所有有效字节的 8 位累加和。

RX 只有在包数完整、图片 ID 和序列号匹配、长度合法且累加和正确时才发送 `0x10` 应答。TX 在首次发送完成后等待一次应答；未在 30 ms 内收到匹配应答时，只重发全部 DATA 和 END，不再发送 BEGIN，也不再等待第二次应答。

## 5 RX 状态机

1. Radio 中断只检查硬件 CRC 并把 254 字节复制到环形队列。
2. 主循环读取队列并按命令分发，避免在中断里执行 UART 和日志。
3. BEGIN 校验图片长度、包数和二者关系，然后创建新的重组上下文。
4. DATA 校验图片 ID、序列号和包编号，去重后写入 20 KB 图片缓冲区。
5. END 检查已收包数并计算累加和。
6. 校验成功后切换到 TX，连续发送两次 ACK，再恢复 RX。
7. 生成 STM 帧并通过 1 Mbps UART 发送。

## 6 RX 到 STM 帧格式

| 偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 4 | 固定同步头 `FF 55 12 34` |
| 4 | 1 | `0x81` |
| 5 | 2 | 后续载荷长度，大端 |
| 7 | 128 | DeviceInfo |
| 135 | 可变 | JPEG |
| 最后 | 1 | JPEG 8 位累加和 |

DeviceInfo 的字节 11 至 18保存胶囊序列号。当前移植版将尚未取得来源的其他设备信息字段清零，后续可接入版本号、RSSI、天线号和时间字段。

## 7 STM32 数据路径

USART2 连接 nRF RX，配置为 1 Mbps。USART3 连接电脑，也配置为 1 Mbps。USART1 保持 115200，仅输出日志。

USART2 和 USART3 均使用循环 DMA。IDLE、DMA 半满和 DMA 满事件把新增数据复制到应用环形缓冲区；主循环从环形缓冲区取出最多 256 字节并调用协议层。因此协议解析不依赖 DMA 分段，也不要求整帧一次到齐。

STM 解析器依次搜索同步头、读取长度并接收帧体。长度合法范围为 128 至 20128 字节。完整帧通过累加和校验后：

1. 提取 128 字节 DeviceInfo；
2. 提取 JPEG；
3. 使用 `IMG00001.JPG` 形式的文件名创建或覆盖文件；
4. 写入 JPEG 并执行 `f_sync`；
5. 将原始完整帧转发到 USART3；
6. USART3 收到的控制数据透明转发到 USART2。

## 8 错误处理

- Radio 硬件 CRC 错误包不进入主循环。
- 图片长度超过 20000 字节时拒绝开始包。
- 包数与图片长度不一致时拒绝开始包。
- 重复数据包不会重复覆盖计数。
- 图片不完整时不发送 ACK。
- 累加和错误时丢弃图片。
- UART 环形缓冲溢出会累计并输出丢失字节数。
- SD 卡不可用时记录错误，系统仍维持通信。
- 文件写入前后刷新 IWDG，写完执行同步并关闭文件。

## 9 当前实现边界

当前版本已经实现原始图像主链路。以下功能应作为下一阶段接入：

- 胶囊序列号写入 nRF Flash；当前 TX 使用全 `FF` 默认序列号。
- RX 绑定序列号过滤、查询、解绑和设置命令。
- 2400 至 2500 MHz 频道参数的持久化。
- DeviceInfo 中版本、RSSI、天线和时间字段。
- STM 文件名加入胶囊序列号和 RTC 时间，避免重启后覆盖同名图片。
- STM 到 PC 的非阻塞 DMA 发送；当前完整帧使用阻塞发送。

这些边界不会改变已经确定的 Radio 参数和图像包格式，但在正式产品联调前必须完成。

## 10 上板验证顺序

1. 单独编译 RX、TX 和 STM，确认零错误、零警告。
2. 不接摄像头，使用固定 254 字节包验证 2 Mbps Radio 参数一致。
3. 验证 RX P0.23 在接收时为低、发送 ACK 时短暂为高。
4. 使用短 JPEG 验证 BEGIN、DATA、END 和 ACK。
5. 人为丢弃一个 DATA 包，确认 RX 不应答、TX 仅重发 DATA 和 END；RX 应保留第一轮正确包并忽略第二轮重复包。
6. 验证 STM USART2 为 1 Mbps 且无溢出日志。
7. 验证 SD 卡生成的 JPG 能正常打开。
8. 验证 USART3 收到的帧与 RX 输出逐字节一致。
9. 连续运行并检查 Radio 队列丢包、UART 丢字节、SD 错误和看门狗复位。

## 11 构建环境说明

工程提供 GCC 和 Keil 配置。本次环境未安装工程配置指定的 GNU Arm Embedded Toolchain 9 2020 q2，命令行构建在启动编译器前停止。代码仍需在本机 Keil 或安装正确 ARM GCC 后完成最终编译和硬件验证。
