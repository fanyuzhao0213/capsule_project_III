# 胶囊控制协议与透传边界

## 总体链路

控制链路为：`PC ↔ STM32 ↔ NRF_RX ↔ NRF_TX`，但按命令归属分层处理。

- STM32 只解释 RTC 时间设置命令 `0x02`，其余 `ZAYS` 控制帧原样转发。
- NRF_RX 本地处理当前会话的绑定、解绑和绑定查询（`0x20～0x25`），不把这些命令发给 NRF_TX。
- RX 绑定状态只保存在 RAM；断电或复位后自动恢复未绑定。
- NRF_TX 只处理上电配置窗口内的出厂 SN 配置（`0x40～0x47`）。
- 未绑定时 RX 不接收图片；绑定后只重组、应答并转发 SN 匹配的图片。
- 图像使用原有无线分片、重组和 ACK 机制；STM32 发给 PC 时使用 `ZAYS + 0x81`。

## 统一控制帧

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| 帧头 | 4 | 固定 `5A 41 59 53`（ASCII `ZAYS`） |
| 命令 | 1 | 见命令表 |
| 数据长度 | 2 | 大端，高字节在前 |
| 数据 | N | 可为 0 字节 |
| 校验和 | 1 | 数据区逐字节累加，取低 8 位；无数据为 `00` |

## 命令归属

| 命令 | 方向 | 处理端 | 数据 |
| --- | --- | --- | --- |
| `0x02` | PC → STM32 | STM32 | 年、月、日、星期、时、分、秒，共 7 字节 BCD |
| `0x20` | PC → NRF_RX | NRF_RX | 查询本次上电会话的绑定状态，无数据 |
| `0x21` | NRF_RX → PC | NRF_RX | 已绑定 SN（8 字节）；未绑定时为 8 个 `00` |
| `0x22` | PC → NRF_RX | NRF_RX | 解除本次会话绑定，无数据 |
| `0x23` | NRF_RX → PC | NRF_RX | 1 字节结果：`01` 成功、`00` 失败 |
| `0x24` | PC → NRF_RX | NRF_RX | 绑定 SN，8 字节 |
| `0x25` | NRF_RX → PC | NRF_RX | 1 字节结果：`01` 成功、`00` 失败 |
| `0x40` | PC → NRF_TX | NRF_TX | 出厂SN配置准备，无数据 |
| `0x41` | NRF_TX → PC | NRF_TX | 准备应答，无数据 |
| `0x42` | PC → NRF_TX | NRF_TX | 查询芯片DEVICEID，无数据 |
| `0x43` | NRF_TX → PC | NRF_TX | 芯片DEVICEID，8字节 |
| `0x44` | PC → NRF_TX | NRF_TX | DEVICEID 8字节 + 待设置SN 8字节；仅暂存 |
| `0x45` | NRF_TX → PC | NRF_TX | 回显暂存SN，8字节 |
| `0x46` | PC → NRF_TX | NRF_TX | 确认把暂存SN写入Flash，无数据 |
| `0x47` | NRF_TX → PC | NRF_TX | 确认写入成功，无数据 |
| `0x49` | NRF_TX → PC | NRF_TX | 出厂SN配置错误，无数据 |
| `0x05` | NRF_TX → NRF_RX → PC | NRF_TX | 当前生效 SN，8 字节；配置成功立即发 3 次，之后每 300 ms 广播 |
| `0x81` | NRF_TX → PC | 各端协作 | JPEG 图片数据 + 128 字节设备信息 |

## 无线可靠性

- 出厂配置短控制请求和应答无线各发送 3 次；绑定管理在 NRF_RX 本地执行，不占用无线链路。
- NRF 硬件 CRC 负责每个 254 字节 Radio 包的链路校验。
- 图像使用独立分片编号、整图累加校验和及接收 ACK，不与短控制帧状态混用。

## 两套SN协议的区别

- `0x40～0x49` 是出厂SN配置协议。先读取目标胶囊DEVICEID，再发送“DEVICEID + 新SN”，最后使用`0x46`二次确认后才写入Flash。
- `0x20～0x25` 是 NRF_RX 当前上电会话的绑定管理协议，用于查询、解除绑定或绑定 SN；不写 Flash。
- 两套协议相互独立：STM32仅透传，NRF_RX截获`0x20～0x25`，NRF_TX只保留`0x40～0x47`。

## 当前联调模式

- 当前 `IMAGE_TRANSMISSION_ENABLED = 1`：NRF_TX 每300ms请求采集并发送图片；改为0时只保留SN广播。
- SN 配置成功后立即广播 3 次，随后主循环每 300 ms 广播一次。
- 图片采集请求周期为 300 ms；上一帧未完成时跳过本次请求。
